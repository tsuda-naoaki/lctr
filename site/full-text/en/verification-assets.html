Formal-Verification Assets

The supplementary archive lctr-verification.zip contains formal-verification assets for Sections 2–6. Its top-level directory after extraction is lctr-verification/. The assets include a complete inventory of the mathematical definitions, formulas, claims, and proof obligations in this scope for the same version as the published PDF, the Lean and Isabelle formalization sources, and a correspondence table linking locations in the Japanese and English PDFs to both formalizations. The table records types, quantification, premises, domains, all conclusions, and dependencies component by component, and links each formula occurrence to the mathematical object it expresses.

The mathematical proof obligations in this scope are formalized in both Lean and Isabelle, and their proofs are checked by the Lean kernel and the Isabelle/Pure inference kernel. Lean proofs are additionally rechecked by the separate implementations nanoda and con-leche. For each formalized object in Lean and Isabelle, the assets include verification results, the axioms used, and theorem dependencies.

For each proof obligation in the text, the assets include a comparison tracing the proof bodies, definitions used, actual theorem dependencies, and local assumptions in both formalizations. The comparison links the premises and conclusions in the text to the dependencies and dependent-type or carrier conditions in both formalizations.

The partial output map of a law-candidate relation has machine-readable representations in MMT, OpenMath, and Content MathML, together with the results of checking these representations. The assets also include SMT proofs and checks of their proof traces, symbolic computations using computer algebra systems, unit and dimension checks, and results from checking counterexamples and boundary cases, together with the conditions under which each check applies. Each result is linked to its object in the text and records the domain and conditions checked.

The release package contains pinned version information for the verifiers and their library dependencies, the inputs and outputs of every included check, reports for each object, and instructions for running each standard tool directly. To establish file identity, the accompanying file manifest associates the name of each published PDF, formalization source, check input, verification result, and rerun script with its SHA-256 hash. The reproduce.sh script runs the included checks and regenerates their reports in the pinned verification environment. The release metadata identifies the verification-assets version corresponding to this PDF, its scope, and the checks performed.
